未来你进入企业级开发的话，产品、前端、后端、测试都是你一个人做的话你觉得开发流程是怎么样的

有没有用过 Spring AI

用过，Spring 生态 Java AI 开发框架，一套抽象接口，可切换不同大模型服务商，内置 ChatClient、Embedding、向量库、FunctionCall，适合 Java 后端快速接入大模型能力。

自己接大模型主要做过什么

基于 Spring AI 搭建 RAG 知识库问答；文档切片、向量化存入向量库；用户提问做语义检索，把召回文档 用户问题一起丢给大模型；实现流式输出、工具调用、提示词管理；做答案校验、引用溯源，降低幻觉。

什么是大模型幻觉

模型生成看起来通顺、自信，但和事实不符、凭空编造的内容，比如编造文档、参数、人名。

大模型为什么会产生幻觉

模型本质是预测下一个 token，不是理解事实；没有真实知识库，只学习文本分布；遇到知识盲区时，模型倾向于生成通顺文本，而不是说 “不知道”；训练数据冲突、知识过时、采样随机性也会加重幻觉。

有哪些方法可以缓解幻觉

1、RAG 检索，给模型提供参考原文，答案锚定文档2、提示词约束：要求不确定就说不知道，输出标注来源3、降低 temperature，减少随机生成4、思维链 / 自校验：模型生成后再自己核查5、工具调用：查数据库、搜索，用外部事实校验6、领域微调、答案后校验

RAG 是什么

检索增强生成（Retrieval-Augmented Generation）。用户提问，先从私有知识库检索相关片段，把检索片段和用户问题一起送入大模型，让模型基于检索材料回答，而不是只靠模型内部参数知识。

为什么RAG能降低大模型幻觉

把模型从 “闭卷考试” 变成 “开卷考试”，给模型提供可信参考上下文，约束模型只能基于给定材料作答，减少凭空编造；知识存在外部向量库，不用重新训练模型就能更新知识。

飞书单点登录：
OAuth2 登录完整流程

用户访问业务系统 → 跳转飞书授权页 → 用户授权 → 飞书回调业务系统，带回code → 业务后端拿code请求飞书获取access_token → 用 token 拉用户信息 → 完成登录，下发身份凭证。

state 是干什么的

防 CSRF 攻击；回调时校验 state 和下发时一致，防止攻击者伪造授权回调。

为什么还要绑定浏览器标识

防止 state 被劫持复用；把 state 和浏览器指纹 / UA 绑定，就算 state 泄露，换浏览器也无法完成回调。

一次性 ticket 为什么要存在 Redis

ticket 只能使用一次；Redis 支持自动过期、快速删除，消费后立刻删，简单实现一次性。

Lua 为什么能保证 ticket 原子消费

Redis 单线程执行 Lua 脚本，查询 删除在同一个原子脚本内，不会出现并发请求同时读到同一个 ticket。

ticket 换 JWT 这种操作叫什么

令牌交换（Token Exchange）

除了换 JWT，还能不能换 Session

可以，ticket 也可以用来创建服务端 Session。

Session 和 JWT 有什么区别

Session：服务端存会话数据，客户端只存 sessionId；有状态，服务端要存储。
JWT：身份信息编码在令牌里，客户端携带；无状态，服务端不存会话数据。

为什么项目最后选择 JWT

适合分布式、多服务单点登录；不用跨服务共享会话存储，扩展性好；网关 / 微服务可直接校验，不用每次查会话库。

JWT无状态是不是意味着没有“会话”这个概念

不是。无状态指服务端不存储会话数据，仍然存在用户本次访问的会话上下文，只是会话信息放在令牌里。

（Agent 双 Agent 项目）难点：单 Agent 幻觉高、长链路错误链式传播，缺少可靠自校验。方案：设计主执行 Agent 校验 Judge Agent 双架构；每一步执行完成由 Judge 校验事实、规划合理性；增加轨迹快照、失败重规划；搭建自动化评测集量化幻觉率。最终降低任务失败率、幻觉指标明显优化。

还有没有别的有难点的项目

分布式 / 高并发：比如高并发数据推理服务：难点是流量波动大、资源浪费、超时不稳定；解决：消息队列削峰、负载均衡、重试幂等、容器弹性扩缩容，增加埋点可观测性。

什么是缓存穿透、缓存击穿、缓存雪崩？

缓存穿透：查根本不存在的数据，缓存 DB 都空，请求直达 DB
缓存击穿：单个热点 key 过期，并发请求全部打到数据库
缓存雪崩：大批量缓存 key 同一时间失效，数据库瞬间高并发打崩

什么是限流？什么是熔断？什么是降级？

限流：限制请求流量，防止突发大量请求压垮服务，控制单位时间允许访问的请求数量。
熔断：依赖的下游服务故障超时 / 报错率过高时，直接切断调用，不再请求故障服务，避免雪崩。
降级：系统压力大或下游异常时，主动舍弃非核心功能，返回兜底简化数据，保住核心业务可用。

寿司算法

给一个数x，求1到10^16是否存在a，使得len(a)*sum(a)=x；这里的sum是指将a的每一位相加（例如：10=》1+0=1）；找符合的最小的a，如果不存在返回-1；
