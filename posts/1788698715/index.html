项目简介

我做的是一个基于 LangChain、RAG 和大模型结构化输出的智能旅行规划平台。用户输入目的地、日期、预算、偏好和旅行节奏后，后端首先通过城市解析判断该目的地属于本地攻略覆盖城市还是动态城市。
对于已覆盖城市，系统通过 Query Rewrite、Embedding、ChromaDB 向量召回和 qwen3-rerank 重排序获取相关攻略；对于动态城市，系统调用高德地图获取景点、餐厅和酒店候选池，要求 Planner 只能返回候选池中的 POI ID，从而降低模型虚构地点的风险。
Planner 使用 LangChain 的 ChatOpenAI 兼容接口调用 DashScope 模型，输出 JSON 草稿，后端再通过 JSON 提取、Pydantic 校验和业务规则校验转换成统一的 Itinerary。模型只负责非确定性的行程规划，预算拆分、地图补全、天气查询和数据持久化由服务层完成。
项目中比较有挑战的是 RAG 结果质量和外部服务失败问题。我通过 Query Rewrite、Rerank、目的地 metadata 过滤、Redis 缓存和规则 fallback 解决；动态城市则通过真实 POI 候选池和 ID 白名单限制模型输出。当前项目采用显式工作流编排，还没有引入 LangGraph，后续计划增加 Validator、自动修复、异步任务队列和可观测性。
