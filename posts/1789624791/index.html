一、DeepAgents 框架核心

LangChain、LangGraph、Deep Agents的区别与联系？

三者是同生态、分层堆叠、可组合的关系，不是互斥竞品：

  • LangGraph = 底层状态图运行时（持久化 Checkpoint、状态、人在回路、流式、断点恢复）
  • LangChain = 组件抽象 + 极简 Agent 循环层（模型 / 工具 / RAG / 检索海量集成，create_agent 轻量 Agent 封装）
  • Deep Agents = 上层开箱即用 Agent 脚手架 (Harness)，构建在 LangChain + LangGraph 之上，自带规划、虚拟文件系统、子 Agent、上下文压缩、长任务记忆等预设能力

所有 LangChain / Deep Agents 的 Agent 底层执行都是编译到 LangGraph 运行；也可把二者作为节点嵌入自定义 LangGraph 大图。

技术选型什么时候使用？

优先选 LangGraph

需要显式状态、自定义分支跳转、混合确定性代码 + LLM 步骤、人工审批断点、持久长流程、完全控制图结构时。

例：业务审批流水线、带校验 / 分支的 RAG、自定义多 Agent 编排、需要重试 / 暂停 / 恢复的工作流。

优先选 LangChain (create_agent)

普通轻量 Agent、工具调用循环、RAG 问答、快速对接任意模型 / 工具、希望自己定制 middleware、不需要内置规划 / 子 Agent / 文件系统时。

例：文档问答、简单工具助手、快速 PoC、想自主组装 Agent 能力。

优先选 Deep Agents

长耗时、高自主、复杂拆解型任务，不想从零实现上下文管理 / 任务规划 / 子 Agent 隔离时。

例：代码 Agent、深度调研、写作 / 数据分析、多子任务委派、需要外置文件承载大上下文。

一句话总结选型口诀：

自定义流程控制 → LangGraph

简单工具 Agent / 快速集成 → LangChain

长任务自主深度 Agent → Deep Agents
